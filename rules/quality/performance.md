# 效能與資源使用

<a id="performance-measurement"></a>
## 效能承諾與量測

1. **關鍵操作的目標**。專案須依業務承諾選出關鍵操作，明訂量測的起點、終點、預期負載與驗收門檻。若承諾涵蓋工作完成，等待排程與排隊的時間也須計入。具體數值由專案決定。
2. **代表性與可重現性**。驗收須定義能代表實際使用情境且可重現的條件，包括資料規模與分布、同時執行的工作，以及影響結果的快取狀態與資源配置。記錄測試環境與實際環境中會影響判讀的差異。
3. **統計母體與成功條件**。每項指標須明訂納入哪些操作，以及如何認定成功。計算期限內成功比例時，所有符合驗收條件的操作都須計入分母，包括失敗與逾時。若另外統計成功請求的延遲，須標明其範圍。指標定義與觀察窗口依[日誌、稽核與可觀測性](observability.md#metrics-and-freshness)。
4. **效能退步**。關鍵操作須選定可追溯的比較基準，在可比較的條件下量測。事先定義退步判定條件與複測方式，分別判讀是否符合業務門檻，以及相對基準的變化是否需要調查。

<a id="resource-limits-and-admission"></a>
## 資源上限與工作受理

5. **單次與併發用量**。資源消耗會隨工作量成長的操作，須依風險限制單次操作的用量與併發執行的總消耗。例如報表分批讀取可限制單次記憶體占用，同時也須評估多份報表爭用資料庫連線的上限。具體限制依容量與業務需求決定。
6. **滿載處置**。須依業務承諾明訂容量達上限時是否受理新工作。允許排隊時須限制佇列容量，並定義期限與逾期處置。回覆須讓使用者能區分已受理等待執行與未受理。
7. **共用資源**。會爭用資源的工作須依業務承諾明訂關鍵操作的保障方式，並在具代表性的混合負載下驗證。例如結帳與匯出使用不同佇列但共用資料庫時，驗收須涵蓋兩者同時執行的情境。
8. **釋放資源與回收名額**。工作結束後須及時釋放資源。逾時或取消時，依契約決定停止或繼續工作。若應停止，須將停止要求傳到執行端。需在呼叫端取消後繼續完成的工作，依[錯誤處理的取消要求](../coding/error-handling.md#cancellation)設計獨立背景流程與結果查詢。確認對應資源已釋放後，才能回收名額。

<a id="sustained-load-and-changes"></a>
## 持續負載與變更管理

9. **持續負載與恢復**。有資源累積或工作積壓風險的流程，須在具代表性的持續負載下驗證用量與積壓趨勢。若允許暫時積壓，須驗證負載回落後能在約定期限內恢復。測試時長依風險決定。
10. **效能改善與業務保證**。須以量測找出瓶頸，在可比較的條件下驗證改善幅度，並核對可能受影響的資料新鮮度、授權範圍或處理順序等業務保證。若要調整既有保證，須另行確認並更新契約。
11. **容量重估**。關鍵資源須依實際用量、預期成長與調整容量所需的時間，明訂重新評估容量的觸發條件。已知的流量或工作量變化須納入判斷。
12. **上線前重新驗收**。程式、設定、基礎設施或依賴的變更若可能影響既有效能承諾或資源上限，須在上線前依風險重新驗收受影響的範圍。驗收方式見[效能與資源驗收](#acceptance)。

<a id="lazy-processing-cost"></a>
## 延遲資料處理的成本

<a id="bounded-accumulation"></a>
### 限制資料累積

可能大量或持續成長的資料，不得無限制地收集成記憶體集合。須依使用需求明訂載入與處理範圍，選擇分頁、分批或逐筆處理。使用迭代器或串流 時，仍須確認來源與操作的實際資料累積及資源成本，不因採用延遲處理語法就推定有界；排序、去重與分組也須評估保留資料的成本。

<a id="acceptance"></a>
## 驗收

驗收案例的選擇與維護依[驗收共同原則](testing.md#acceptance-principles)。

依效能與資源使用，在上線前針對變更影響的操作與共用資源選擇案例。

- 記錄比較版本、負載、資料分布、環境差異與指標口徑，使量測可以重現。例如 1,000 筆有效查詢中有 940 筆在期限內成功、40 筆較晚成功、20 筆逾時，期限內成功比例應為 94%。分別判讀業務門檻與相對基準的變化，符合複測條件時依約複測。
- 同時施加關鍵與背景工作負載，核對單次用量、總占用及關鍵操作的成功率與延遲。達到執行和排隊上限時，分別核對回覆、實際受理結果與逾期處置。模擬取消或逾時，確認工作依契約停止或繼續，且名額隨實際資源釋放而回收。
- 對有累積風險的流程，持續觀察資源占用、佇列深度或最舊工作的等待時間。若允許尖峰積壓，降低負載後核對恢復所需時間。另依實測用量、成長趨勢及容量調整所需時間，檢查是否已達容量重估條件。
- 對效能改善，核對變更前後的量測結果及受影響的業務行為。例如以快取降低延遲時，須同時驗證快取命中後仍符合授權與資料新鮮度契約。
