# 安全共通規範

<a id="authorization-and-data-scope"></a>
## 授權與資料範圍

公開能力及可匿名存取的資料須明訂於契約。其餘能力採預設拒絕、明確允許。伺服器須依可信身分判斷「誰能在什麼範圍內，對哪個對象執行哪項操作」。缺少必要資訊、沒有允許規則或授權服務故障時，須在揭露受保護資料或產生業務副作用前停止。內部須區分權限不足與授權服務故障，對外依[錯誤處理](../coding/error-handling.md#failure-classification)及存在性揭露政策回應。

- 人員與服務身分都只取得職責需要的操作與資料範圍。操作對象、可讀欄位及可寫欄位分別授權。只允許遮蔽值時，伺服器須在回傳前遮蔽；無權修改的欄位即使格式正確，伺服器仍須拒絕該變更。
- 集合操作在選取資料時即套用授權與租戶範圍，涵蓋列表、總數、匯出及批次寫入。請求中的租戶、門市或物件 ID 僅指定目標。混有越權項目時，依批次契約整批拒絕或只處理獲准項目，回應仍須遵守存在性揭露政策。
- API、背景工作、事件處理及其他入口均須執行必要檢查。代使用者執行時，有效權限取使用者與服務權限的交集。系統自行發起的排程使用專用服務身分與明確授權。兩者都須可追溯發起者、執行者與授權依據。
- 延後執行的工作預設在實際讀取或變更時重新查核權限。若流程在發起者失去權限後仍須持續，核准時須建立獨立授權，綁定操作、對象、期限及撤銷條件。

<a id="permission-changes-and-review"></a>
## 權限變更與獨立覆核

- 授予、擴大及撤銷他人權限本身須獨立授權。伺服器限制管理者可處理的對象、範圍及權限，防止替自己或他人越權提權。異動須記錄操作者、對象及權限範圍的變化。
- 撤權或縮小範圍須定義並驗證最晚生效時間，涵蓋既有工作階段、權杖及快取。要求立即生效的操作，下次執行時即須依新權限判斷。
- 專案依風險列出需再次驗證身分的操作、可接受的方式及有效期間。驗證未完成或過期時停止操作，通過後仍須判斷操作權限。
- 需獨立覆核的操作，伺服器須確認申請人與核准人不同、核准人有該範圍權限，且實際執行內容與核准相符。影響決策的欄位變更後須重新送審，並保留申請、核准與執行的關聯紀錄。

<a id="identity-and-account-lifecycle"></a>
## 跨服務身分與帳號生命週期

- 指定可信的身分來源與傳遞方式。接收端須能驗證身分資訊由獲授權的上游建立，且傳遞途中受到保護。若由閘道設定身分標頭，須移除或覆寫外部同名標頭，並防止呼叫者繞過閘道偽造身分。
- 各接收端明訂可接受的憑據類型，依機制驗證可信來源、適用服務、用途及有效期間。共用驗證機制須涵蓋所有受保護的路徑，驗證通過後仍須執行業務授權。
- 登出目前裝置時終止該工作階段與續期能力。停用帳號時停止新登入與續期。疑似憑據外洩時，撤銷範圍須涵蓋可用來換發新憑據的途徑。各情境須定義受影響的既有憑據、失效時限，並驗證失效結果。
- 帳號復原須驗證申請人身分，依原因撤銷受影響的工作階段與驗證器。無法界定範圍時，依事先定義的較廣失效策略處理。完成後透過可信管道通知持有人。
- 一次性連結與驗證碼須綁定帳號、用途、目標及期限，成功使用即失效。併發提交時也只能成功一次。登入、復原及發碼流程分別限制猜測次數、發送頻率及總量。依風險選擇帳號、目標及來源等限制範圍，防止重新發碼或切換入口規避限制，也應避免第三人藉此長期鎖住帳號。
- 對無權查詢帳號狀態的人，登入與復原回應的文字、狀態碼及可見欄位均應避免揭露帳號存在性、停用狀態與聯絡方式。內部保留實際原因供授權人員診斷。系統故障致使請求無法受理時，如實回報暫時無法處理。

權限異動、核准與敏感查閱的稽核內容、保存及調閱要求見[日誌、稽核與可觀測性](observability.md#required-audit-events)。

<a id="secrets-and-credentials"></a>
## 秘密與憑據

- 由核准機制集中管理秘密，在執行時依服務身分與環境提供必要憑據。禁止將秘密值寫入版本庫、前端程式、容器映像或日誌。必要秘密缺失時停止相依功能，診斷僅指出設定名稱。
- 每項秘密須可查到負責人、使用服務及環境、輪替與撤銷方式。例行輪替時確認新憑據可用，於明訂期限內撤銷舊憑據。供應方只允許單一憑據時，事先安排切換與失敗處理。
- 疑似外洩時依暴露範圍與風險撤銷或停用，不能沿用例行輪替寬限期。即使已刪除版本庫中的秘密，仍須處理已暴露的憑據。確認服務恢復，並依供應方狀態或受控驗證確認舊憑據失效。異動紀錄使用識別碼、時間與結果。
- 使用者密碼以成熟函式庫提供的專用單向密碼雜湊保存，每筆使用獨立隨機鹽值，成本參數依環境與風險調整。只需比對的高熵隨機權杖可保存可驗證摘要。短碼須另外考量離線猜測風險。需要取回原值的第三方金鑰依秘密存取規則保存。

<a id="sensitive-data-and-copies"></a>
## 敏感資料與副本

- 各類資料依用途定義必要欄位、可存取對象、保存期限或刪除條件。用途變更時重新確認授權與保護要求。
- 盤點受控的快取、搜尋索引、匯出檔與備份，為每類副本定義清除或去識別化期限。線上副本仍能回傳資料時，不得回報刪除完成。備份無法逐筆清除時，限制存取並明訂到期清除方式；還原後須先套用有效的刪除紀錄，才重新開放查詢。
- 敏感資料跨服務、傳送第三方或交付使用者時，須加密傳輸並驗證接收端，內網亦適用。主資料庫與各類副本依分類和風險明訂儲存加密要求。解密權限獨立界定，例如複製備份的工作僅需存取密文。

<a id="input-output-and-deserialization"></a>
## 輸入、輸出與反序列化

- 查詢值使用參數綁定。欄位名稱、排序方向等動態結構由伺服器依允許清單映射至預定義結構。執行系統操作優先使用函式庫；必須啟動外部程式時固定執行檔，分開傳遞參數，依程式語意驗證，避免資料被解讀成選項。
- 一般文字依輸出位置使用框架轉義或純文字介面。連結另驗證允許的協定與用途。只有契約允許的富文字可保留經成熟工具清理的標記，限制標籤、屬性及連結協定。腳本與樣式使用可區分資料與可執行內容的介面。已存入資料庫的外部資料仍適用這些要求。
- 反序列化只接受契約列出的業務類型，由伺服器映射至對應模型。外部輸入不得選擇任意內部類別或驅動執行行為。框架的多型反序列化也適用，未知類型或不合法欄位組合須在業務操作前拒絕。

<a id="file-upload-and-delivery"></a>
## 檔案上傳與交付

- 各用途明訂格式、大小、數量及處理成本。副檔名與使用端宣告的類型僅供初篩，伺服器須以適合該格式的解析器驗證實際內容，拒絕損壞或不支援的檔案。接收時限制大小與數量，解碼與解壓縮時另限展開尺寸、總量或項目數。
- 業務使用或下載前須完成必要檢查。背景檢查期間隔離待驗證檔案。伺服器產生檔案 ID 與儲存鍵，原始名稱只供顯示，依網頁或下載標頭的輸出位置處理。
- 寫入與解壓縮限於指定區域，拒絕可藉絕對路徑、上層目錄或符號連結逸出區域的項目。下載須查核物件歸屬與讀取權限，限時下載連結須綁定物件與期限。

<a id="server-fetch-and-browser-boundaries"></a>
## 伺服器代抓網址與瀏覽器邊界

- 固定用途使用核准的服務位址，由使用端提供目標識別碼。接受公開網址時，限制協定、連接埠與實際連線位址，阻擋回環、私有網路、鏈路本地及雲端中繼資料服務等目的地。
- 對允許的重新導向逐跳重新檢查，確保名稱解析在檢查與連線之間不能改指受限位置。使用專用受限連線設定，限制等待時間及回應大小，不夾帶 Cookie、內部授權標頭或服務憑據。
- 瀏覽器自動附帶憑據且會變更狀態的入口須有 CSRF 防護。優先使用框架機制驗證可信來源或有效防偽權杖。涵蓋表單及 API 等適用入口，驗證失敗須在產生副作用前拒絕。
- 帶憑據的跨來源讀取只允許業務需要的來源。CORS 依協定、主機及連接埠精確比對允許清單，限縮方法與標頭，禁止原樣放行任意 Origin。API 授權、CORS 及 CSRF 須分別驗證。

安全驗收案例見[本文件驗收](#acceptance)。依風險決定的門檻、協定、工具及期限由專案明訂，例外遵循[規範治理](../workflow/rule-governance.md#exception-approval)。

## 動態載入與呼叫目標

<a id="dynamic-target-authorization"></a>
<a id="rf-02"></a>
### 受控目標與授權

動態載入、建立或呼叫的目標須由受控登錄或允許清單限定，不得直接依未受信任輸入解析並執行任意類別、方法或建構子。未知目標須明確拒絕，目標符合型別也不能取代授權檢查。

<a id="acceptance"></a>
## 驗收

驗收案例的選擇與維護依[驗收共同原則](testing.md#acceptance-principles)。

<a id="安全驗收"></a>

依各能力的失敗後果與入口，選擇接近合法操作的越權案例，同時驗證拒絕結果、對外揭露與實際副作用。測試資料、憑據與目的地須依[共通測試策略](testing.md#test-data-and-environments)隔離，預期行為以安全共通規範為準。

- 例如具備 A 門市退款權的客服提交 B 門市訂單時，確認該操作遭拒、回應未違反訂單存在性揭露政策、訂單及帳務未變更，且未送出退款請求。對允許部分成功的批次，分別核對獲准與越權項目的效果。
- 依功能涵蓋跨租戶、集合計數、可讀不可寫欄位、自行核准、代理執行與排程執行前撤權。對可能繞過共同檢查的 API、背景或事件入口，驗證相同的權限邊界。
- 核對授權服務故障時安全停止、舊工作階段與權杖按時失效、停用後不能續期、併發提交的一次性憑據僅成功一次，以及跨入口無法繞過嘗試與發送限制。
- 依適用情境驗證秘密輪替後的失效與服務恢復、敏感資料副本清除與備份還原，以及惡意輸入、檔案、重新導向與未知反序列化類型能在產生副作用前受到限制。對瀏覽器入口分別驗證未授權的跨來源讀取與跨站狀態變更。
