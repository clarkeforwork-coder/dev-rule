# 資料遷移與大量操作

本文件定義結構變更、新舊版本相容及大量資料操作的共通要求。具體遷移工具、批次門檻與部署流程由專案決定。

<a id="versioned-migrations"></a>
## 版本化遷移

- 正式環境的資料表、欄位、索引與約束等結構變更，必須可追蹤、可重現，以版本化遷移檔隨程式碼管理並接受審查，不只靠人工直接修改。
- 已在共用環境套用的遷移不得直接改寫；需要修正時新增遷移，保留歷史。
- 執行前評估既有資料、鎖定時間、執行成本與服務影響，不只確認語法正確。
- 明確定義失敗後的恢復方式；無法安全回退時可以向前修復，不強制每個變更都有反向遷移。
- 緊急人工調整須經核准並記錄，事後補齊遷移管理與狀態核對，避免環境結構長期不一致。

<a id="version-compatibility"></a>
## 新舊版本相容

- 新舊程式可能並存時，必須分階段維持相容，不將破壞性結構調整與程式切換視為瞬間完成。
- 先新增相容欄位或結構，再部署能配合過渡狀態的程式。
- 資料搬移必須安排可追蹤、可恢復的回填，並驗證完整性。
- 過渡期間若有雙寫，必須定義主要資料來源與寫入失敗處理，不假設兩份資料自然一致。
- 確認舊版本及其他使用端已不再依賴，且回退需求已處理後，才能移除舊欄位或約束。
- 可接受停機的專案可採較簡單切換流程，但仍須規劃停機、備份與恢復方式。

<a id="bulk-data-operations"></a>
## 大量回填、修正與刪除

- 執行前確認篩選條件、預期筆數與影響，先預覽或試跑。
- 依資料量分批，限制交易大小與速率，避免長時間鎖定或耗盡資源。
- 記錄處理進度，中斷後必須可安全續跑，不重複產生副作用。
- 線上資料仍在變動時，明確處理併發衝突，避免舊資料覆蓋較新修改，並遵守[交易與併發控制](transactions.md#concurrent-updates)。
- 破壞性操作事先定義備份或其他可行恢復方式，依專案權限流程核准。
- 完成後核對實際筆數、失敗項目與資料完整性，不只以腳本正常結束判定成功。

遷移及大量操作依[本文件驗收](#acceptance)測試相容、恢復與續跑。例外及架構影響依[規範治理](../workflow/rule-governance.md#exception-approval)處理。
