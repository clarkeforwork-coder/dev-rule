# 設定管理與環境差異

<a id="configuration-contract"></a>
## 設定契約與讀取責任

- 每個元件須界定自己管理的設定範圍。逐項定義名稱、用途、型別、單位、合法範圍、是否必填及省略時的行為。只有未提供的設定才能使用契約明訂的預設值。已提供但無效的值須回報錯誤。
- 契約須列明設定來源、優先順序與各來源可覆寫的項目。同一優先層出現衝突且沒有明訂裁決方式時，須在套用前回報並拒絕該次設定。
- 相同用途的設定在各環境維持一致的名稱、型別與語意。環境專屬項目及允許的差異須列入契約。
- 元件只檢查自己負責的範圍。範圍內出現未定義的名稱時，須指出該名稱並拒絕該次設定，即使正確名稱有預設值也一樣。
- 負責的元件統一讀取、轉型與驗證，使用處只接收所需的具型別設定。例如付款用戶端接收已驗證的時長，由設定入口處理環境變數的字串格式與單位。[型別安全](../coding/type-safety.md#型別轉換)

<a id="activation-updates-source-failure"></a>
## 生效、更新與來源失聯

- 契約須明訂設定在啟動、重新載入或其他時點生效。啟動與更新都須在套用前驗證。關聯設定須整組驗證、一次切換，更新失敗時整組維持原值。對進行中的操作，須明訂何時沿用原版本、何時重新確認新版。
- 設定來源不可用時，契約須明訂能否使用最後一次驗證成功的版本、可沿用多久及期限起算點。讀取失敗不得延長期限。沒有可用版本或期限屆滿時，須停止契約指定的受影響操作。
- 錯誤須能定位設定項目與原因。來源資訊僅揭露可安全顯示的部分。即使底層解析例外包含原始輸入，錯誤訊息、日誌與診斷介面也不得帶出敏感值。例如連線字串缺少主機時，可指出設定名稱與缺少的部分。秘密管理與紀錄分別依[安全共通規範](../quality/security.md#秘密與憑據)及[日誌、稽核與可觀測性](../quality/observability.md#診斷日誌與追蹤)。

<a id="deployment-compatibility-rollback"></a>
## 部署、版本相容與回退

- 每次部署須依待部署程式版本的契約，驗證目標環境依優先順序合併後的設定。只能在執行環境取得的設定可於啟動時驗證。新實例通過驗證後才能接收請求、消費訊息或執行其他工作。
- 設定變更須可追溯，並能核對各實例實際生效的版本。回退前須確認舊設定仍適用於目前的程式版本與執行環境。
- 契約變更須明訂遷移順序，涵蓋新舊版本並存期間。新增必填項目須分階段提供與要求。改名或更換單位須定義對應、換算方式及新舊值並存時的裁決方式。確認執行中與可能回退的版本都已解除依賴後，才能移除舊設定。
- 若新行為需要多個實例或服務配合，契約須明訂可安全啟用的條件，確認條件成立前維持相容行為。例如，同一佇列仍有只能讀取舊格式的消費者時，發布端須繼續使用舊格式。

<a id="temporary-feature-flags"></a>
## 暫時性功能開關

建立暫時性開關時須指定負責人、檢視時間與清理條件。到期仍須保留時，負責人須記錄原因與下次檢視時間。清理條件成立後，先讓程式固定採用選定的行為，再依版本相容順序移除設定值。

設定契約測試與每次部署的驗收要求見[本文件驗收](#acceptance)。

<a id="acceptance"></a>
## 驗收

驗收案例的選擇與維護依[驗收共同原則](../quality/testing.md#acceptance-principles)。

<a id="設定管理驗收"></a>

依[設定管理與環境差異](../workflow/configuration.md#設定契約與讀取責任)，分別驗證程式的設定入口與每次部署實際使用的設定。

- 設定契約變更時，須透過實際設定入口自動測試受影響的生效與拒絕情境。例如以不同來源驗證覆寫順序，以拼錯的名稱、無效值或同層衝突驗證拒絕結果。使用虛構敏感值時，核對診斷輸出未帶出原值。
- 支援執行中更新時，先載入有效設定，再送入組合不合法的新設定，從使用處確認整組仍維持原值。變更失聯策略時，驗證允許沿用的期限、重試不延長期限及到期停止的操作。
- 每次部署須驗證待部署版本能接受目標環境合併後的設定。驗證失敗的新實例不得開始處理工作。分階段啟用或回退時，核對實例生效版本與相容條件。移除設定前，確認執行中與可能回退的版本均已解除依賴。

- 更新會影響進行中的操作時，驗證沿用舊設定或重新確認新設定的行為符合契約。跨實例或服務切換時，核對啟用前提已成立。
- 審查暫時性功能開關的負責人、檢視時間與清理條件。保留或移除時，核對延期理由或相容遷移順序。
