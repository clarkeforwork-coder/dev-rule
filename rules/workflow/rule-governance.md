# 規範治理

<a id="gradual-adoption"></a>
## 漸進導入

- 新增程式碼必須完整遵守規範。
- 修改既有程式碼時，新增與修改部分必須符合規範；受舊介面限制時，明確提出並個別決策。
- 未修改的舊程式碼記錄待改善範圍並分批處理，不要求每次任務全面重構。
- 自動檢查記錄既有違規作為基準，阻擋新增違規；已修正項目不得退回違規狀態。
- 既有違規與例外必須精確限定範圍，不得為此關閉整個專案的檢查。

<a id="precise-violation-baseline"></a>
<a id="精確違規基準"></a>
<a id="au-05"></a>

### 精確違規基準

既有違規基準須辨識具體規則及位置，不只比較總數。已修正項目須移出基準，更新不得吸收新增違規或以一項修正抵銷另一項新問題。原有漸進導入與精確例外範圍仍適用。

<a id="architecture-changes"></a>
## 架構變更

改變架構約束前，必須先說明影響並由專案負責人確認，再進行實作。適用情況包括：

- 新增原本不允許的跨層或跨模組依賴。
- 移動業務規則或資料的管理歸屬。
- 改變模組公開入口慣例。
- 拆分、合併模組，或將模組拆成微服務。

決策必須記錄理由、受影響的使用端與遷移方式，並同步更新架構文件與相關檢查。符合既有邊界的日常功能開發與內部重構不需逐次取得架構核准。架構變更若涉及降低共通基準，仍須經下列例外核准流程，不因修改架構文件而自動豁免。

<a id="generated-code"></a>
## 工具產生碼

本節指 API、ORM 等產生器的輸出。AI 撰寫的程式碼仍視為自行撰寫，必須完整遵守規範。

- 優先設定產生器，使產出符合型別安全要求。
- 產出集中存放，與手寫程式碼區分；修改來源或產生器設定後重新產生，不直接修改產出。
- 產生器無法符合要求時，必須個別討論並記錄，不自動豁免，也不降低整個專案的標準。
- 產生碼若具有不安全型別，其影響必須限制在銜接元件內，不得擴散到內部契約；手寫銜接程式仍遵守禁止主動繞過檢查的要求。

<a id="generated-code-exceptions"></a>
<a id="rf-07"></a>

### 產生碼不擴大豁免

產生碼依本文件的[工具產生碼](#工具產生碼)管理，優先透過產生器版本、設定、範本與來源使產出符合規範；不能直接修改產出掩蓋可重現的來源問題。不得以產生碼問題放寬手寫程式碼的檢查；手寫銜接仍維持明確型別與驗證，重新產生後須確認核准範圍與內部型別契約仍成立。

<a id="exception-approval"></a>
## 例外核准

開發者與 AI 不得自行放寬規範。遇到限制時，先提出具體阻礙、影響範圍與已評估的替代方案，由專案指定負責人決定；個人專案由專案擁有者決定。

核准例外必須記錄：

- 核准人與決策結果。
- 涉及的規範、原因與精確適用範圍。
- 已評估的替代方案、風險與補償措施。
- 重新檢視的時間或條件。

例外只適用於核准範圍，不得自動延伸到其他地方。涉及禁止事項也必須取得明確例外決策，不能以工具限制自行略過。專案應在自己的決策文件中保留可追溯紀錄。

<a id="suppression-scope"></a>
<a id="檢查抑制與產生碼治理"></a>
<a id="rf-06"></a>

### 限定檢查抑制

檢查抑制須有可核對的原因，限定具體規則與最小必要範圍，不得廣泛關閉檢查掩蓋違規。型別安全限制依既有例外流程核准；其他誤報處置須先確認原因與配置，保留判定依據及重新檢視條件，並在相關程式或工具變更時重新確認。不得將尚未處理的真實違規當成誤報。

<a id="acceptance"></a>
## 驗收

驗收案例的選擇與維護依[驗收共同原則](../quality/testing.md#acceptance-principles)。

<a id="violation-baseline-acceptance"></a>
### 違規基準驗收

驗收：核對原違規、修正及新違規的差異；相同總數但位置／規則改變仍能辨識，新違規不能透過基準更新放行。

<a id="supplementary-contract-acceptance"></a>
<a id="補充契約驗收"></a>
### 補充契約驗收

| 契約 | 驗收內容 |
| --- | --- |
| <a id="acceptance-suppression-scope"></a>[限定檢查抑制](#suppression-scope) | 核對抑制規則、最小範圍、判定依據及適用核准。以代表性檢查案例確認範圍外仍受檢查，沒有因抑制一項問題而關閉整個類別、模組或專案的必要檢查。 |
| <a id="acceptance-generated-code"></a>[產生碼不擴大豁免](#generated-code-exceptions) | 依實際來源與設定重新產生，確認產出及例外範圍可重現，手寫銜接仍符合型別契約。工具或產生器更新時，重新確認例外依據，未沿用已失效的抑制。 |
