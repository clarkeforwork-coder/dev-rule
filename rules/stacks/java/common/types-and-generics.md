# Java 型別宣告與泛型

本文件只維護 Java 的具體要求；引用的共通規範同樣具有約束力。

本文件承接[共通型別安全](../../../coding/type-safety.md)，適用於自行撰寫的 Java 程式碼，包含測試與整合元件。語法及 API 須符合[適用範圍與版本判定](version-policy.md)。

## 明確宣告與型別關係

1. **明確宣告型別**。參數、回傳值、欄位與區域變數須明確宣告型別，保留必要的泛型資訊，不使用 `var` 取代型別標註。
2. **禁止 raw type 與不必要的型別抽象**。使用泛型型別時須宣告型別參數，禁止 raw type。承載業務語意的參數、回傳值與欄位須保留業務所需的型別資訊，不得以 `Object`、萬用字元或無必要的泛型隱藏已知型別。泛型與萬用字元僅在確有型別抽象需求，且能維持必要約束與關聯時使用；不僅依所在層級或是否出現 `?` 判定合理性。
3. **輸入與輸出的型別關聯**。依[型別安全](../../../coding/type-safety.md)執行。Java 泛型簽章須實際連結輸入與輸出的型別；特定業務操作直接使用其型別，不要求呼叫端轉型補回。
4. **不得以向下轉型補回業務型別**。自行撰寫的程式碼不得以強制向下轉型補回遺失的業務型別資訊，應透過資料契約、泛型或多型設計保留型別。外部資料須在邊界完成驗證與明確型別轉換，不能讓型別不明的資料流入業務流程。工具或第三方 API 限制須依例外流程個別處理，不預先開放整合處例外。本項針對參考型別的向下轉型，數值轉換另依適用規範處理。
5. **型別安全警告**。新增或修改程式碼不得留下 raw type 或 unchecked 警告，須修正造成警告的契約與實作，不得以 `@SuppressWarnings` 或關閉檢查規避要求。工具限制須依例外流程個別核准，記錄影響範圍、型別安全依據與驗證方式。

既有程式碼的漸進導入、工具產生碼與個別例外依[規範治理](../../../workflow/rule-governance.md)辦理。測試不得透過不安全轉型偽造有效物件，另見[測試程式碼要求](../../../quality/rule-verification.md#測試程式碼)。

## 資料結構與泛型契約

6. **業務資料結構**。依[型別安全](../../../coding/type-safety.md)執行。例如固定欄位資料不得改以 `Map<String, Object>` 或 `Object[]` 承載；真正動態的映射仍須保留明確鍵值型別。
7. **型別能力與約束**。泛型操作所需的型別能力與關聯，須透過型別參數、上界或明確的參數契約表達，不得依賴未宣告的型別假設、執行期猜測或強制轉型。無實際通用需求時，直接使用明確型別，不為使用泛型而額外建立介面。
8. **集合與映射的宣告型別**。宣告型別須表達使用端所需的操作與語意，優先使用能完整表達契約的介面；不得過度泛化而迫使使用端轉型，也不應無必要地暴露具體實作類別。可修改性、排序方式等保證須依契約另行明訂，不僅憑集合介面推定。
9. **允許建構端使用菱形運算子**。變數已明確宣告完整型別時，允許使用 `<>` 省略建構時重複的泛型參數；不得因此省略宣告端所需的型別資訊或改用 raw type。
10. **泛型回傳值**。回傳值須提供明確、可直接使用的型別；只有契約確實需要表達未知型別或其上下界時，才使用萬用字元，不得為預留彈性而增加使用端負擔，也不得以萬用字元取代不可變性設計。
11. **泛型參數命名**。名稱須能辨識用途與關聯。簡單情境可使用 `T`、`K`、`V` 等通行慣例名稱；具有不同責任或較複雜關聯時，應使用能表達角色的名稱，例如 `Source` 與 `Target`，並在必要時補充契約說明，不強制所有泛型參數使用長名稱。

例如，下列宣告保留元素與鍵值型別，並允許建構端省略重複資訊；其中 `ordersById` 表達依識別碼查找訂單的關係，不是用任意欄位名稱拼湊單一訂單：

```java
List<Order> orders = new ArrayList<>();
Map<OrderId, Order> ordersById = new HashMap<>();
```

固定結構的訂單輸入則應使用明確物件，例如 `CreateOrderRequest`。邊界物件的拆分與映射責任另依[邊界物件](../../../architecture/boundary-objects.md)與[資料映射](../../../architecture/data-mapping.md)。

## 驗收要求

共同驗收與 Java 語言增量均須經實際採用的 Java 型別、API、版本與框架銜接路徑執行，不因引用共通驗收而略過。依變更範圍核對下列項目，包含受影響的呼叫端與測試程式碼。測試層級及證據依[共通測試策略](../../../quality/testing.md)與[規範驗證](../../../quality/rule-verification.md)；可自動判斷的要求依[規範驗證](../../../quality/rule-verification.md)納入檢查，型別是否表達正確業務語意則由人工審查。
