# Java 例外與資源管理

本文件只維護 Java 的具體要求；引用的共通規範同樣具有約束力。條號保留供既有決策與驗收追蹤，不代表引用條目另有一套政策。

本文件承接[錯誤處理](../../../coding/error-handling.md)，定義 Java 例外傳遞、中斷及資源生命週期的共同要求。預期業務失敗依[狀態與結果建模](states-and-results.md)使用明確結果型別；元件建立及延遲讀取的所有權另依[類別、介面與物件建立](classes-and-construction.md)與[集合與資料所有權](collections-and-ownership.md)。

## 例外契約與捕捉責任

1. **明確的故障分類**。例外型別須能表達契約所需的故障分類，避免無必要的籠統宣告或拋出，例如一律使用 `throws Exception` 或沒有明確語意的 `RuntimeException`。既有標準或第三方例外足以表達且符合架構隔離時，不強制自訂例外。需要邊界轉換時，須保留原始原因，不改變故障語意，也不將預期業務失敗改用例外表示。
2. **Checked 與 Unchecked 的選擇**。須依故障語意及呼叫端的處理責任選擇，同類契約維持一致慣例。需要呼叫端明確處置或向上宣告的技術故障可使用 Checked Exception；由統一入口處理的故障或程式缺陷，可使用適當的 Unchecked Exception。不得只為省略宣告或捕捉而任意轉換，也不得僅依例外是否受編譯器檢查，就判定能否恢復或重試。
3. **捕捉範圍與處置相符**。優先捕捉具體例外並縮小 `try` 範圍，不得將不同來源的故障一律轉成同一業務結果。最外層入口可依責任統一處理尚未處理的例外，但仍須保留分類，不得假裝恢復成功。不得以廣泛捕捉 `Throwable` 或 `Error` 掩蓋嚴重故障並繼續操作。
4. **保留中斷意圖**。`InterruptedException` 須依呼叫契約向上傳遞；無法傳遞而在本層捕捉時，須恢復中斷旗標並停止或依明確取消契約處理。不得吞掉中斷後照常執行或自動重試，必要清理不得掩蓋中斷意圖。

## 資源所有權與失敗清理

5. **優先使用語言資源管理機制**。由目前操作負責關閉且支援 `AutoCloseable` 的資源，優先使用 `try-with-resources`，讓使用範圍與關閉時機對應，涵蓋正常完成及例外退出。借用或框架管理的資源依所有權契約處理，不得擅自關閉。其他生命週期須明訂可靠的釋放方式，不以垃圾回收代替必要的資源管理。
6. **保留操作與清理失敗**。操作與清理同時失敗時，須保留原始例外及清理例外的關係，不得覆蓋或遺失 suppressed exceptions。使用 `try-with-resources` 時須保留其記錄的清理例外，自行清理時也須維持故障關係。不得以 `finally` 中的 `return` 或其他控制流程掩蓋原結果；單獨發生的清理失敗也須依資源契約判斷完成保證與回報方式，不得默默忽略。
7. **部分取得與所有權移交**。依[部分取得與所有權移交的共通要求](../../../coding/resource-lifecycle.md#ex-07)執行。Java 多資源取得及建構失敗亦須清理；資源移交前仍由取得方負責，釋放順序遵循依賴。
8. **有效期與關閉契約**。依[有效期與關閉契約的共通要求](../../../coding/resource-lifecycle.md#ex-08)執行。Java `AutoCloseable` 資源不可在非同步工作仍使用時提前關閉，不無依據假設所有 `close()` 都可重複呼叫。
9. **失敗路徑驗收**。例外處理或資源生命週期新增及變更時，須依影響驗證故障分類、原因保留、中斷傳遞與適用的資源釋放路徑，涵蓋部分初始化及清理失敗，並確認所有權與實際使用期間一致，不僅驗證成功流程。涉及框架管理的生命週期時須驗證實際配置，不能只靠替身推定正確；不要求每個方法套用全部情境。

故障日誌與對外回應仍須遵守[日誌、稽核與可觀測性](../../../quality/observability.md)及[資料契約](../../../interfaces/data-contracts.md)，不因保留例外原因而直接對外揭露內部資訊。

## 驗收要求

下表保留原決策編號與 Java 實作案例。共通原則依各條連結的主要來源及其驗收執行；Java 型別、API、版本與實際框架銜接路徑仍須完成下列適用驗收，不因原則提升而略過。

依操作風險、實際資源與責任選擇案例，沿用[共通測試策略](../../../quality/testing.md)及[規範驗證](../../../quality/rule-verification.md)。

| 對應決策 | 驗收內容 |
| --- | --- |
| 1、2、3 | 核對例外型別、宣告、轉換及捕捉範圍是否符合契約與處置責任。以適用的不同故障來源驗證分類，確認業務失敗、技術故障與程式缺陷未混淆，包裝後仍保留原始原因。 |
| 4 | 對可中斷的操作送出中斷，確認依契約向上傳遞，或在無法傳遞時恢復旗標並停止或取消；沒有吞掉後繼續等待、執行或重試，必要清理仍正確完成。 |
| 5 | 分別驗證正常完成、提前退出與操作失敗時釋放自行擁有的資源，借用與框架管理資源未被擅自關閉。核對非區域生命週期的釋放責任，不依賴垃圾回收。 |
| 6 | 模擬操作與清理同時失敗，確認原始故障及 suppressed exceptions 或相應故障關係可追查，未被 `finally` 的控制流程覆蓋。另驗證只有清理失敗時的完成判定與回報。 |
| 7 | 在後續資源取得或初始化步驟製造失敗，確認先前已取得的資源依正確順序釋放。核對所有權移交前後的責任，避免洩漏或不當重複關閉。 |
| 8 | 驗證實際使用期間資源持續有效，尤其是委派及非同步路徑；核對關閉後操作與重複關閉依契約處理，不假設可繼續使用或重複關閉必定安全。 |
| 9 | 核對案例覆蓋變更影響的故障、中斷與清理路徑。依賴框架行為的保證須有實際生命週期驗證，不只測試替身或成功流程。 |

既有程式碼、工具限制與必要例外依[規範治理](../../../workflow/rule-governance.md)處理，不自行放寬要求。
