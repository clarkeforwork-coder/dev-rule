# Java 併發與非同步處理

本文件只維護 Java 的具體要求；引用的共通規範同樣具有約束力。條號保留供既有決策與驗收追蹤，不代表引用條目另有一套政策。

本文件承接[錯誤處理](../../../coding/error-handling.md)與[效能與資源使用](../../../quality/performance.md)，定義 Java 併發工作的所有權、同步、結果及生命週期。中斷與資源清理另依[例外與資源管理](exceptions-and-resources.md)，具體 API 須符合[版本要求](version-policy.md)。

## 工作所有權與執行資源

1. **明確的工作擁有者**。依[明確的工作擁有者的共通要求](../../../coding/concurrency-and-async.md#ca-01)執行。Java 任務脫離呼叫流程時仍須有明確接手元件及結果處置路徑。
2. **統一管理執行資源**。依[統一管理執行資源的共通要求](../../../coding/concurrency-and-async.md#ca-02)執行。Java 可用明確提供的 `Executor`、`ExecutorService` 或框架提交工作；虛擬執行緒也須遵守下游容量。
3. **可見性與共享資料**。跨執行緒資料須透過具備可見性保證的方式交付，優先使用不可變資料或符合契約的隔離快照。需要共享可變狀態時，須明訂同步與原子性範圍，不得以單一 `volatile` 欄位或偶然成功的執行結果推定整個物件安全。

## 期限、取消與結果

4. **等待期限與逾時處置**。依[等待期限與逾時處置的共通要求](../../../coding/concurrency-and-async.md#ca-04)執行。Java 非同步等待的逾時不代表底層工作已停止；等待 API 須承接整體時間預算。
5. **取消傳遞與實際停止**。依[取消傳遞與實際停止的共通要求](../../../coding/concurrency-and-async.md#ca-05)執行。Java 取消訊號及中斷依任務契約傳遞，不把取消最外層 Future 視為全部子工作已停止。
6. **結果接收與故障處置**。非同步任務的成功、失敗與取消結果須有明確接收及處置路徑，不得忽略回傳的工作控制物件而遺失故障。`Future`、`CompletableFuture` 等結果須由負責元件處理；結果鏈中的例外轉換須保留原因與分類，只有契約允許的恢復或降級才能轉成替代結果，不得一律以空值或預設值將失敗變為成功。
7. **多工作組合的完成條件**。依[多工作組合的完成條件的共通要求](../../../coding/concurrency-and-async.md#ca-07)執行。Java 多工作組合須驗證完成順序及剩餘任務處置，第一個完成不等於第一個成功。

## 執行位置、脈絡與同步

8. **執行位置與阻塞行為**。依[執行位置與阻塞行為的共通要求](../../../coding/concurrency-and-async.md#ca-08)執行。Java 任務及回呼須明確安排 executor 與阻塞行為，避免占用同一受限 executor 等待其排隊工作。
9. **明確傳遞與清理脈絡**。依[明確傳遞與清理脈絡的共通要求](../../../coding/concurrency-and-async.md#ca-09)執行。Java 不假設 `ThreadLocal` 或日誌脈絡自動沿用；共用執行緒上的脈絡須在結束時清理或還原。
10. **鎖定範圍與取得策略**。依[鎖定範圍與取得策略的共通要求](../../../coding/concurrency-and-async.md#ca-10)執行。Java 同步與鎖的實作須涵蓋全部退出路徑，必要檢查不能為縮短持鎖而移出原子範圍。

## 關閉與驗證

11. **受控關閉**。依[受控關閉的共通要求](../../../coding/resource-lifecycle.md#ca-11)執行。Java 執行元件開始關閉或發出停止要求不代表工作全數結束；實際關閉與資源釋放依共同契約驗證。
12. **可控制的併發驗收**。依[可控制的併發驗收的共通要求](../../../quality/testing.md#ca-12)執行。Java 測試使用可控制的協調與完成條件，並審查同步／可見性設計，不以固定睡眠或壓力測試單獨證明安全。

共享集合的複合操作另依[集合與資料所有權](collections-and-ownership.md)，元件生命週期依[類別、介面與物件建立](classes-and-construction.md)，平行資料處理依[Lambda 與 Stream](lambda-and-stream.md)。身分及延後執行授權依[安全規範](../../../quality/security.md)，追蹤與故障紀錄依[日誌、稽核與可觀測性](../../../quality/observability.md)。

## 驗收要求

下表保留原決策編號與 Java 實作案例。共通原則依各條連結的主要來源及其驗收執行；Java 型別、API、版本與實際框架銜接路徑仍須完成下列適用驗收，不因原則提升而略過。

依受影響流程與風險選擇案例，沿用[共通測試策略](../../../quality/testing.md)與[規範驗證](../../../quality/rule-verification.md)。

| 對應決策 | 驗收內容 |
| --- | --- |
| 1、6 | 核對工作擁有者、責任移交與結果接收路徑；觸發成功、失敗及取消，確認故障可追查，例外分類保留，未以替代值假裝成功。 |
| 2、8 | 核對實際執行配置、各階段執行位置及阻塞關係。依風險模擬容量耗盡、排隊與拒絕，確認不超出下游限制，也不因同一受限資源上的相互等待而無法前進。 |
| 3、10 | 審查資料交付、同步範圍、鎖定與可見性保證，以受控交錯驗證不變條件及共享狀態。核對多鎖策略、退出釋放及持鎖期間的外部操作，不以測試偶然成功代替設計依據。 |
| 4、5 | 驗證期限承接整體預算，逾時與取消後工作依契約停止或受控繼續。確認相關子工作收到所需訊號，未確認停止的工作仍有擁有者，執行名額依實際資源釋放回收。 |
| 7 | 以不同完成順序及子工作失敗驗證全部成功、部分成功或競速等適用契約。核對每項結果與來源對應，剩餘工作持續受到管理，未將最快失敗當成第一個成功。 |
| 9 | 在共用執行資源上交錯執行不同租戶或身分的工作，驗證脈絡正確傳遞，成功、失敗與取消後均清理或還原，沒有跨工作污染。核對延後執行的授權仍依契約確認。 |
| 11 | 在排隊及執行中仍有工作時啟動關閉，核對停止受理、等待期限、取消或接手安排與資源釋放順序。期限後未完成或未知結果仍可追蹤，不被當成已結束。 |
| 12 | 確認案例使用明確的協調與完成條件，等待有期限且失敗保留診斷資訊，涵蓋受影響的交錯與故障路徑。壓力測試結果須搭配同步及生命週期審查，不作為唯一安全證據。 |

既有程式碼、框架限制與必要例外依[規範治理](../../../workflow/rule-governance.md)處理，不自行降低要求。
