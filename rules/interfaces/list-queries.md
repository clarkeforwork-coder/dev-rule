# 列表 API 的分頁、篩選與排序

## 筆數與分頁方式

- 專案依資料量與成本決定每頁預設及最大筆數，並寫入契約。省略時使用預設值。格式錯誤、非正數或超限時回報驗證失敗，不自動調整。
- 禁止以特殊參數解除筆數上限。大量匯出使用獨立操作。固定且規模受控的小型集合可在契約說明其範圍後免分頁。底層查詢遵循[資料存取與完整性](../data/persistence.md)。
- 專案依使用需求與資料變動程度定義選用原則，同類列表採一致慣例。需要跳頁且資料量與變動可控時，可採頁碼或偏移量。持續新增、大量資料或連續瀏覽可採游標。
- 契約須說明翻頁期間新增、修改或刪除資料是否可能造成重複或遺漏。若保證某一時點的資料皆可讀取一次，須提供快照或等效機制。單靠游標或穩定排序無法提供此保證。

## 游標與續查

- 使用端原樣傳回游標，不解析、修改或自行組合。伺服器須驗證游標並將它綁定原查詢的篩選、排序與必要範圍。變更條件須重新查詢。
- 契約須定義有效期限或失效條件。游標無效、過期或與條件不符時回報可辨識的錯誤，不默默退回第一頁。
- 每次續查均依當下授權檢查資料範圍。游標不得暴露秘密或不必要的敏感資料。依需要提供防竄改機制，不能依賴編碼保密或證明內容可信。具體保護與儲存方式由專案決定。
- 回應須定義取得下一頁以及辨識最後一頁的方式，例如提供下一頁游標並定義末頁如何表示。即使最後一頁剛好滿頁，使用端也能依契約判定結束。

## 排序與篩選

- 契約列出可排序欄位、方向與預設順序。排序值可重複時，使用唯一識別欄位作最後排序依據。多欄排序須定義優先順序，空值位置、大小寫或語系影響比較時也須說明。翻頁途中改變排序須重新查詢。
- 可篩選欄位須列明型別及允許的運算子。多條件須定義 AND／OR 的組合方式。範圍須說明是否包含端點，適用時定義空值、空字串與大小寫的比較方式。
- 排序及篩選只接受契約允許的輸入。禁止任意資料庫欄位、SQL 片段與未受限制的運算式。未知欄位、不支援的方向、運算子或組合、格式錯誤及矛盾範圍均回報驗證失敗。
- 依支援能力限制條件數、集合長度與巢狀深度。使用端條件只能縮小已授權的資料範圍，不得覆蓋伺服器的授權與租戶隔離條件。

## 總筆數

是否提供總筆數由業務需求決定。未知時可省略，不得填入 `0`。估算值必須標明。總數與列表須套用相同的篩選、授權及租戶範圍。資料會變動時，契約須說明計數與頁面是否共用快照，所宣告的一致性須符合實際保證。

列表的組合測試與驗收見[規範驗證](../quality/rule-verification.md)。
