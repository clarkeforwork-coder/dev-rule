# 外部整合可靠性

本文件定義外部呼叫、重試、冪等性、資源隔離與結果確認的共通要求。數值門檻、儲存與併發機制由專案依契約、服務特性及業務風險決定，不強制特定工具。

<a id="timeouts-and-deadlines"></a>
## 逾時與整體期限

- 所有外部呼叫必須設定明確的時間限制，包括適用的連線與回應逾時，不得無限等待或直接沿用未確認的框架預設值。
- 同一業務操作的多次呼叫、重試與等待必須共用整體期限，不得每次重試重新取得完整額度。
- 下游呼叫應配合上游剩餘時間；不足以完成時，不再啟動新嘗試。
- 長時間作業使用適當背景處理與結果查詢，不單靠延長同步等待。
- 逾時仍遵循[結果未知原則](../coding/error-handling.md#unknown-outcome)，不得直接認定對方未執行。

<a id="safe-retries"></a>
## 安全重試

- 只有可能屬於暫時性故障，且重複執行安全時，才允許自動重試。
- 暫時性連線問題、服務短暫不可用與流量限制，依對方契約評估；輸入錯誤、權限不足、業務拒絕與程式缺陷，不透過原樣重試處理。
- 查詢必須確認實際行為，不能只因名稱是查詢就視為安全。
- 寫入、扣款、通知等有副作用的操作，須確認前次未執行，或具有明確冪等保證，才能重試。
- 逾時本身不是重試許可。結果未知時，先依既定方式確認；契約保證相同操作識別碼可安全重送時，才可依該機制處理。

<a id="retry-management"></a>
## 重試管理

- 同一外部操作指定單一重試管理位置，例如 SDK、整合元件或流程協調元件，避免各層重試疊加。
- 必須確認 SDK／框架內建重試，納入整體次數與時間預算。
- 設定最大嘗試次數並明確包含首次呼叫，等待與執行均計入整體期限。
- 自動重試採逐步增加的等待間隔及隨機偏移，避免大量請求同時重送。
- 遵守對方提供的重試等待指示；若超過整體期限，停止本次同步重試。
- 收到取消訊號或失去安全重試條件時，停止後續嘗試。

<a id="idempotency"></a>
## 冪等性

冪等性要求同一操作重複送達時，不重複產生業務效果。

- 需要安全重送的操作使用穩定操作識別碼或冪等鍵，重試沿用，不重新產生。
- 明確定義識別碼作用範圍，例如使用者、商戶與操作類型，避免不同操作互相誤判。
- 相同識別碼搭配不同業務內容時，拒絕處理，不直接沿用舊結果。
- 重複請求依既有操作狀態取得先前結果或明確的處理中狀態，不再次執行副作用；結果未知時仍須明確表達，不能假定仍在處理。
- 必須處理同時到達的重複請求，不只使用有競爭空隙的「先查再執行」。
- 定義紀錄保留期限及過期行為，並確認第三方實際提供的保證；只傳送冪等鍵不代表對方已實現冪等性。

<a id="resource-and-failure-isolation"></a>
## 資源與故障隔離

- 明確限制同時呼叫數、連線數與等待佇列，不得無限堆積。
- 依風險決定是否使用熔斷：持續失敗時暫停一般呼叫，有限探測確認恢復後逐步放行。
- 不同外部服務應有適當資源隔離，避免單一服務故障耗盡所有工作執行緒或連線。
- 超出容量或暫停呼叫時，明確回報暫時不可用，或使用已核准的降級，不得假裝成功。
- 不要求所有整合採用同一套複雜機制，具體門檻與隔離方式由專案決定。

<a id="acceptance-and-completion"></a>
## 接受與完成

- 依契約區分已接受、處理中與已完成，不得把傳輸成功當作業務完成。
- HTTP 成功狀態或訊息發布確認，必須依對方契約解讀，不單靠狀態碼判定最終結果。
- 非同步操作提供可追蹤識別碼，透過查詢或結果事件確認最終狀態。
- 需要下游業務完成的流程，必須定義完成依據與等待期限，超時後進入既定結果確認或異常處理。
- 重複或延遲結果仍遵守冪等、順序與狀態轉換規則；回報狀態必須符合已確定進度。

<a id="overdue-detection-and-reconciliation"></a>
## 逾期偵測與結果核對

- 需要最終結果的非同步流程，必須能查找長時間未完成的工作，記錄操作識別碼、目前狀態及必要時間資訊。
- 定義預期完成時間，超過後觸發查詢、對帳或人工處理，不直接判定業務失敗。
- 不只依賴結果事件，依風險提供主動核對方式，偵測遺失或未完成流程。
- 核對與修復仍遵循冪等、順序及結果未知原則，不盲目重送。
- 指定後續處理責任，依風險選擇自動核對或受控人工流程，不強制建立複雜對帳系統。

<a id="callbacks-and-event-sources"></a>
## 外部回呼與事件來源

- 外部回呼與事件先驗證來源，再進入業務處理。依契約使用簽章、服務身分驗證或其他可信機制，不只相信來源欄位與內容。
- 依協定使用簽章涵蓋的原始資料驗證，不先任意修改內容。
- 有時效或防重放要求時，驗證時間範圍與唯一識別資訊等條件，同時依契約處理合法重送。
- 來源驗證不得取代[資料驗證](../coding/validation.md#validation-responsibilities)、業務授權與冪等處理。
- 驗證失敗不得執行業務副作用，須留下不含秘密資訊的必要安全紀錄。
- 內部訊息系統也必須設定發布與訂閱權限，不因位於內網就默認可信。

跨服務身分、金鑰管理與目的地限制見[安全共通規範](../quality/security.md#identity-and-account-lifecycle)。事件發布與消費見[事件可靠性](events.md#recoverable-publication)，故障測試見[本文件驗收](#acceptance)，例外依[規範治理](../workflow/rule-governance.md#exception-approval)處理。

<a id="外部整合與事件故障恢復驗證"></a>

依實際採用的機制與風險，驗證[外部整合](../interfaces/external-services.md#safe-retries)與[事件流程](../interfaces/events.md#acceptance)中斷後能否恢復，以及恢復是否重複產生副作用。適用情境包括：

- 外部呼叫逾時、限流或持續故障下，重試、整體期限與熔斷是否符合設定。

可使用受控環境與故障模擬，不要求在正式環境製造故障，也不要求每個整合套用全部情境。
