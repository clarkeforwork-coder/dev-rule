# 空值語意

- 契約與型別必須明確表達業務需要區分的狀態，不得把未提供、明確清空與有值全部表示為同一個空值。
- 必填資料禁止空值；選填資料明確表達有值或無值。
- 部分更新若需要保留、移除與替換資料，必須表達以下三種意圖。

| 狀態 | 意圖 |
| --- | --- |
| 未提供 | 保留原值 |
| 明確清空 | 移除原值；該欄位必須允許清空 |
| 提供新值 | 依驗證結果更新 |

- 空字串、`0` 與空集合不自動視為缺值，是否允許及其意義由契約定義。
- 預設值必須有明確套用規則，不得用來掩蓋不合法輸入。
- 各語言如何表示上述狀態另行制定，不能只依賴反序列化後無法分辨來源意圖的空值。

行為測試應分別確認省略欄位、明確清空、提供新值與不合法值的結果。例外依[規範治理](../workflow/rule-governance.md)處理。

## 整合與契約演進

<a id="jn-08"></a>

### 第三方空值行為

第三方 API 的空值行為須在整合邊界確認並轉換成內部契約。對方明訂 `null` 表示正常查無資料時，才轉成內部正常缺值；保證不明或違反契約的 `null`，不得直接當成非空使用，也不得擅自解讀為正常缺值。無法確認語意時，須先釐清或明訂處置。

<a id="jn-09"></a>

### 空值契約變更

空值契約變更須評估參數、回傳值及欄位對使用端的影響，涵蓋是否允許缺值、缺值語意、標註及實際處置；即使型別或方法簽章未變，也不得直接視為相容。本要求涵蓋公開介面、模組間契約及專案內部被其他程式碼使用的方法與型別。可同步修改的內部使用端，在同一次變更更新並驗證；無法同步更新時安排相容處理與遷移。型別標註、文件及驗證須同步更新。

## 補充契約驗收

依變更影響及實際採用能力驗證，測試層級與案例維護依[共通測試策略](../quality/testing.md)；不要求每個操作涵蓋全部情境，也不重測語言標準函式庫本身。

| 契約 | 驗收內容 |
| --- | --- |
| [第三方空值行為](#jn-08) | 依第三方契約分別驗證正常缺值及適用的異常空值、故障情境，確認內部轉換保留語意，未一律轉成正常缺值。 |
| [空值契約變更](#jn-09) | 檢查空值契約差異、使用端影響與必要遷移，確認相關標註、文件及驗證同步更新，不僅比對方法簽章。 |
