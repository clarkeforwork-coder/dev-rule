# 資源與元件生命週期

適用於需要取得、初始化、移交、釋放或關閉的資源與元件，包含延遲資料流程及背景工作。物件導向的建立限制只在實際採用該設計時適用，不強制使用 DI 或特定建立模式。

相關共同要求：[框架與依賴組裝](../architecture/dependency-composition.md)、[錯誤處理](error-handling.md)、[併發與非同步](concurrency-and-async.md)。必要例外依[規範治理](../workflow/rule-governance.md)處理。

## 契約要求

<a id="initialization-readiness"></a>
<a id="cl-03"></a>

### 必要資料與依賴齊備

物件建立完成時，須具備維持自身有效性所需的資料與必要依賴，不依賴呼叫端事後補設才能正常使用。需要分階段啟動的元件，須明訂生命週期與可用條件，未就緒前不得接受不符合條件的操作。不因此要求建構子完成外部連線或啟動背景工作。

<a id="shared-lifecycle"></a>
<a id="cl-09"></a>

### 生命週期與可變狀態相容

物件的共用範圍、可變狀態與依賴生命週期須相容，不得讓單次操作資料洩漏到其他操作。例如共用服務不得以實例欄位存放會互相覆蓋的目前使用者或訂單。共享可變狀態須有明確的管理與併發保護；長期元件使用短期依賴時須採生命週期相容的取得方式。由框架建立或注入，不代表自動具備執行緒安全與生命週期正確性。

<a id="lifecycle-verification"></a>
<a id="cl-10"></a>

### 契約與生命週期驗收

類別、介面或建立流程變更時，須依影響驗證建立條件、替代契約、必要檢查與生命週期。涉及框架組裝、代理或共用狀態時，須驗證實際配置及隔離效果，不僅確認物件可建立或依賴可注入；不能只靠手動建立的測試推定框架行為正確。單純值物件不必為此啟動整個框架。

<a id="lazy-resource-lifetime"></a>
<a id="co-07"></a>

### 延遲讀取的資源責任

依賴外部資源的延遲集合、迭代器或串流，須明訂資源擁有者、有效範圍與釋放責任，涵蓋完成、提前停止與失敗情境。不得回傳已失效或關閉責任不明的資料流程；無法清楚維持生命週期時，可在資源有效範圍內完成處理，再回傳範圍受控的結果。

<a id="partial-acquisition"></a>
<a id="ex-07"></a>

### 部分取得與所有權移交

多資源取得或元件初始化須涵蓋部分成功後的失敗清理。所有權正式移交前，由取得方負責釋放已取得資源；移交後由新的擁有者依契約管理。釋放順序須符合資源依賴，避免先關閉仍被其他資源使用的底層資源，不得因建立未完成或責任移交不明造成洩漏。

<a id="resource-close-contract"></a>
<a id="ex-08"></a>

### 有效期與關閉契約

資源有效期須涵蓋實際使用期間，包含委派或非同步工作；關閉後不得再使用。可關閉元件須明訂關閉後操作與重複關閉的處理方式，不得提前關閉仍在使用的資源，也不得無依據地假設關閉操作可重複執行。將資源交給背景工作時，須調整擁有者與使用範圍，而非讓原方法結束就提前釋放。

<a id="controlled-shutdown"></a>
<a id="ca-11"></a>

### 受控關閉

執行元件關閉須明訂停止受理、排隊與執行中工作的處置、等待期限及資源釋放順序。已受理工作依契約等待完成、取消或交由可恢復機制接手；未完成或結果未知的工作須可追蹤並有後續責任。不得將開始關閉或發出停止要求視為全部工作已結束，也不得提前釋放仍在執行工作所需的資源。

## 驗收要求

依變更影響及實際採用能力驗證，測試層級與案例維護依[共通測試策略](../quality/testing.md)；不要求每個操作涵蓋全部情境，也不重測語言標準函式庫本身。

| 契約 | 驗收內容 |
| --- | --- |
| <a id="acceptance-initialization-readiness"></a>[必要資料與依賴齊備](#initialization-readiness) | 以缺少必要資料或依賴的情境驗證建立限制；分階段啟動元件在未就緒時須拒絕尚不允許的操作。 |
| <a id="acceptance-shared-lifecycle"></a>[生命週期與可變狀態相容](#shared-lifecycle) | 涉及共用實例或可變狀態時，依風險以多次或併發操作驗證資料隔離，確認不同使用者或請求不會互相覆蓋。核對實際依賴生命週期與取得方式相容。 |
| <a id="acceptance-lifecycle-coverage"></a>[契約與生命週期驗收](#lifecycle-verification) | 核對測試涵蓋受影響的建立、替代、必要檢查與生命週期保證；需要框架行為才能成立的保證有實際組裝驗證，不以單純注入成功作為全部符合的證據。 |
| <a id="acceptance-lazy-resource-lifetime"></a>[延遲讀取的資源責任](#lazy-resource-lifetime) | 對依賴外部資源的延遲讀取，分別驗證完成、提前停止及失敗後正確釋放，並確認讀取期間資源有效、擁有者與關閉責任明確。 |
| <a id="acceptance-partial-acquisition"></a>[部分取得與所有權移交](#partial-acquisition) | 在後續資源取得或初始化步驟製造失敗，確認先前已取得的資源依正確順序釋放。核對所有權移交前後的責任，避免洩漏或不當重複關閉。 |
| <a id="acceptance-close-contract"></a>[有效期與關閉契約](#resource-close-contract) | 驗證實際使用期間資源持續有效，尤其是委派及非同步路徑；核對關閉後操作與重複關閉依契約處理，不假設可繼續使用或重複關閉必定安全。 |
| <a id="acceptance-controlled-shutdown"></a>[受控關閉](#controlled-shutdown) | 在排隊及執行中仍有工作時啟動關閉，核對停止受理、等待期限、取消或接手安排與資源釋放順序。期限後未完成或未知結果仍可追蹤，不被當成已結束。 |

## 共用元件的責任

委派及非同步的有效期依[有效期與關閉契約](#resource-close-contract)及其[驗收](#acceptance-close-contract)。工作提交、取消與整體結果依[併發與非同步](concurrency-and-async.md)；操作與清理失敗依[清理與補償失敗](error-handling.md#清理與補償失敗)。
