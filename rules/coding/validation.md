# 資料驗證

## 責任分工

- 接收邊界負責結構與格式驗證，例如必填欄位、資料型別、日期格式與支援的狀態值。外部資料通過驗證後，才能當作可信的內部型別使用。
- 業務邏輯負責業務規則驗證，例如餘額是否足夠、訂單是否允許取消；專屬型別建立時維護自身不變條件。
- 已驗證的資料在可信內部流程傳遞時，不必每層重複檢查相同格式；業務操作仍須確認當下條件。
- 靜態型別宣告不能取代外部資料的執行期驗證。
- 實際由哪個元件承擔責任，依專案架構決定。

## 未知欄位

| 情境 | 處理要求 |
| --- | --- |
| 自有 API 輸入 | 預設拒絕契約未定義的欄位，及早發現錯誤或契約不一致 |
| 第三方服務回傳 | 可接受額外欄位，但只擷取已定義且驗證通過的欄位，不帶入內部模型 |
| 事件與訊息 | 依版本與相容性政策決定；需要支援新增欄位演進時可忽略未知欄位 |

忽略未知欄位不得放寬已知欄位的驗證。事件政策及自有 API 的非預設處理必須明確記錄，不依賴框架未經確認的預設行為；偏離規範依[規範治理](../workflow/rule-governance.md)處理。

行為測試應涵蓋合法與不合法輸入、未知欄位政策，以及業務操作當下條件。
