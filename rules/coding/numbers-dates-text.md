# 數值、日期時間與文字處理

適用於內部運算及邊界資料轉換，按實際精度、時間、編碼與比較語意選擇適用要求。具體型別及 API 由語言規範落實；對外格式由公開契約定義，不以環境預設或工具行為代替業務決策。

相關共同要求：[型別安全](type-safety.md)、[領域建模](domain-modeling.md)、[API 操作語意與介面設計](../interfaces/api-contracts.md)、[資料契約](../interfaces/data-contracts.md)。必要例外依[規範治理](../workflow/rule-governance.md)處理。

## 契約要求

<a id="nt-01"></a>

### 依語意選擇數值型別

須依精度、範圍、單位與運算需求選擇型別。需要精確十進位語意的資料不得以二進位浮點數作為精確表示，可依契約使用精確十進位型別或最小單位的整數。允許近似計算時，須明訂誤差與比較規則，並保留必要的業務專屬型別；整數也須評估可能範圍，不僅依目前資料量選擇。

<a id="nt-02"></a>

### 從精確來源建立

需要精確表示的數值須直接從契約允許的十進位文字、整數或其他精確來源建立，不得先經浮點數而遺失精度，再期待轉回精確十進位型別恢復原值。來源本身為近似值時，須明訂精度處理。解析成功仍須驗證業務允許的格式、範圍與小數位數。

<a id="nt-03"></a>

### 明訂捨入規則

可能損失精度的運算須明訂保留精度或小數位數、捨入模式與執行時機，並由負責元件一致實作。不得由各使用端自行捨入或截斷；契約要求精確結果時，無法滿足須明確回報。逐筆捨入後加總與加總後捨入不可未經確認就互換。

<a id="nt-04"></a>

### 範圍與轉換檢查

數值運算與轉換須維持目標型別及業務範圍限制，對可能溢位、縮小範圍或捨棄小數的操作採取明確檢查。不得以強制轉型、溢位回繞或未授權截斷掩蓋超限與精度損失。輸入各自合法不代表運算結果必然合法。

<a id="nt-06"></a>

### 依業務語意選擇時間型別

日期時間型別須依業務語意選擇，明確區分日期、當地日期時間與確切時點。需要時區或偏移資訊時須保留，不得以未帶時區的當地日期時間冒充唯一時點，也不得僅依資料庫或傳輸格式決定語意。各語言優先使用能完整表達所需語意的受支援時間型別。

<a id="nt-07"></a>

### 明確的時區轉換

日期時間轉換須明確指定契約要求的時區或偏移，不得無意依賴系統預設時區。當地時間可能不存在或對應多個時點時，須明訂拒絕、調整或補充資訊等判定與處理規則，不以函式庫預設行為取代業務決策。

<a id="nt-08"></a>

### 區分時間長度與日曆規則

時間長度、日曆間隔與業務日期規則須分別建模，依語意使用時間長度型別、日曆間隔型別或明確的業務計算。不得未經契約定義就將日、月、年換算成固定秒數；月底、假日與時區變化等適用情境須明訂處理方式，不能假設一般日曆間隔已涵蓋營業日規則。

<a id="nt-09"></a>

### 可控制的時間基準

業務中的目前時間須透過可控制的時間來源取得，優先使用明確提供的時鐘。需要一致判斷時共用同一時間基準，避免同次判斷因反覆取時跨過邊界而矛盾。執行耗時與等待期限的計算須使用適合的單調時間來源，不與業務日期時間混用。

<a id="nt-10"></a>

### 解析與輸出契約

日期時間解析與格式化須明訂格式、必要的地區設定、時區或偏移及精度，完整驗證輸入是否合法。不得依賴環境預設或寬鬆解析修正非法日期，也不得只解析輸入前段就視為成功。精度縮減與格式轉換須依契約一致處理，包含儲存或傳輸精度較低的情境。

<a id="nt-11"></a>

### 明確指定字元編碼

文字與位元組轉換須明確使用契約指定的字元編碼，不依賴系統預設。無效編碼或無法表示的字元須依契約拒絕或處理，不得未經允許替換而掩蓋資料損失。讀取與寫入兩端須遵循相同交換契約，不一律強制所有外部系統使用同一編碼。

<a id="nt-12"></a>

### 長度與截取單位

文字長度限制、索引及截取須明訂計算單位，區分位元組、編碼單位、Unicode 碼點與使用者可見字元，不將函式庫預設長度當作通用字數。截取須維持合法編碼及契約要求的字元完整性，不切斷必要的編碼單位或字元組合；儲存位元組限制與業務字數限制須分別確認。具體字串表示及 API 限制由語言規範定義。

<a id="nt-13"></a>

### 用途明確的文字轉換

文字比較、大小寫轉換及正規化須明訂適用範圍、地區設定與等價規則，不無意依賴系統預設。搜尋比對與原值保存可採不同表示，但不得以未經契約允許的轉換改變識別、相等性或原始內容。去除空白、Unicode 正規化及全形半形轉換均依用途決定，不將協定代碼規則直接套用到自然語言資料。領域值的正規化、驗證及相等性關係依[領域建模](domain-modeling.md#vo-05)統一維護。

<a id="nt-14"></a>

### 邊界與環境差異驗收

數值、日期時間或文字處理規則新增及變更時，須依影響驗證邊界值、非法輸入、精度與格式轉換，以及適用的時區、地區與編碼差異。涉及儲存或傳輸時，須確認實際轉換路徑維持契約語意，不僅測試一般輸入。不要求每個欄位測試所有情境，也不重測標準函式庫本身。

## 驗收要求

依變更影響及實際採用能力驗證，測試層級與案例維護依[共通測試策略](../quality/testing.md)；不要求每個操作涵蓋全部情境，也不重測語言標準函式庫本身。
