# ADR 0005：Java 自動檢查工具架構

日期：2026-11-11

狀態：pre-commit 層與 CI 層已實作

## 背景

規範及文件檢查已建立，後續需要讓採用專案在開發與合併前取得一致的 Java 規範檢查；本紀錄保存已核准的工具方向；接入與驗證限制見 tools/java/README.md。

## 決策

Java 自動檢查工具放在 `tools/java/`，分為 IDE 即時回饋、pre-commit 提交前檢查、CI 合併門檻三層，使用一致的規則識別與判定依據。一條工具規則對應一個規範錨點，診斷可追溯到正式要求；規範的違反／符合範例作為工具測試資料，驗證應命中與不應命中的案例。

專案以已審查 commit SHA（或指向該提交的明確 tag）固定引用的規範與工具版本，升級時檢視 CHANGELOG、評估規則變動並驗證後採用；不以浮動分支作為版本承諾。

GitHub 可重用 workflow 僅由 uses 的 revision 決定工具來源，runner 將中立 root 傳入建置；CI 強制政策編譯器並以首次建置的 JUnit XML 確認架構測試實際執行。JUnit 5 為預設；JUnit 4 僅供既有專案過渡（legacy），Gradle 不強制測試框架。Java helper 以原始碼 SHA-256 與 JDK 版本在專案建置目錄重用，不使用跨專案 class 快取；基準獨立呼叫仍暫存編譯。

## 後果

工具、規範及案例須同步維護，錨點變更會影響診斷與測試；三層檢查可提早提供回饋，仍不能取代無法自動判定的語意審查。`tools/java/` 已交付 pre-commit、編譯、位元碼、建置與架構 CI 設定，以及精確違規基準；IDE 使用同一設定，外掛安裝與專案化架構仍由採用端負責。首次版本 tag 另行發布。
