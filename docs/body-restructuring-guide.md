## 工作範圍與並行責任

每位工作者只改被分派的 `rules/stacks/java/common/<主題>.md`、`docs/body-restructuring/java/<主題>.json` 及自己的說明文件。不要改共通規則、其他工作者的 Java 文件、共用差異清單、歷史分類、批次追溯、改寫清單或工具；需要跨檔更新時，把精確連結與改法交給協調者整合。不要重生全部 JSON，避免覆蓋他人的逐句判斷。

尚未整理文件的 `status` 保持 `pending`，整個檔案（含驗收、空白與行尾）須與基準相同。分派到的文件改為 `completed` 後，才能依其差異清單修改。不能透過把其他文件也標為 completed 來擴大範圍。

遇到共通來源沒有直接承接的句子，保留在 Java 並記錄缺口與理由；不要自行新增共通義務或把近似句當作完整涵蓋。標示「是／可能」新跨語言義務的條文整條保留，不抽背景；ND-02 待補證也整條保留。除已核准並獨立列管的 CA-06、CO-08 外，不提升新的跨語言義務。

## 小標題與錨點

正式正文不用流水號。保留有意義的二級主題分組，各條以三級小標題及獨立顯式錨點定位，例如 JN 樣板：

```markdown
<a id="java-optional-nonnull"></a>

### Optional 本身非空

宣告使用 `Optional` 的位置，`Optional` 本身不得為 `null`。
```

錨點用 `java-` 加小寫英文語意，單字以 `-` 分隔，不含歷史 ID 或條號；描述保證或機制，不用泛稱 `rule-1`。同檔唯一，避免與隱含標題錨點相撞。歷史 ID 只留 docs 對照；共通來源連結仍使用目前的 `#jn-08` 等錨點，74 個歷史錨點改名由後續獨立批次統一處理。

分組標題仍有入站連結時，優先保留標題；若確需移除，列出所有入站連結交由協調者更新。不要為保留舊條號而另造一份正文。驗收列的顯式錨點保留，第一欄條號改成小標題連結，第二欄的每個斷言不得改寫或刪除。

## 去向 JSON 的填寫

每份檔案的 `rules` 是歷史 ID 到現行錨點的對照表；全部紀錄合起來必須恰好是原分類的 153 條，不能增刪或移到錯誤文件。`ruby scripts/show-body-map.rb` 可輸出完整對照表，不必多人共同編輯一份表。

- `baseline`、`path` 固定；`status` 為 pending／completed／merged。
- `rules` 的每筆含 `id`、六種 `kind` 之一、非空 `targets` 及 `reason`。targets 為儲存庫相對路徑加錨點，可列多個既有主要來源。
- `sentences` 必須保留基準正文所有原句及順序。工具切分方式為每行去條號與粗體小標題後按句號切句，標點保留；檔頭及非條文段落也納入，不能只追蹤 12 條編號。小標題及空白由全文差異保護。
- `action: 保留`：各目標的 `text` 必須與 `source` 完全一致，並在該錨點的小節內逐字存在。
- `action: 改寫`：保留原 `source`，目標 `text` 貼上實際承接文字，逐句寫出共同背景的來源與 Java 斷言如何保留；共同背景列在 `common_sources`，每個錨點也會驗證。不用整檔、無關段落或只有連結的句子掩蓋內容缺漏。
- `action: 移除`：targets 必須是涵蓋原句的共通條文錨點；reason 指出具體斷言與來源，不得只寫「共通已涵蓋」。機器只能證明錨點存在，涵蓋程度必須人工逐句讀。
- `acceptance_changes` 逐筆填 `before`、`after`（保留換行）及理由，僅供第一欄條號改連結。第二欄不得改動；不變的列不必登錄。
- `edits` 是基準 1 起算行號、逐字 remove／insert（每行含換行）及理由。只描述這份檔案，不放其他檔案的差異。

填完去向後，可用輔助指令更新全文差異；它不會代填或核准句子去向，也不會改其他文件：

```sh
ruby scripts/update-body-diff.rb null-and-optional 'JN 依逐句去向改為語意小標題，驗收內容完整保留並只更新條號連結。'
```

每句不是單純保留時，理由至少 20 個非空白字元；字數通過不代表正確。樣板為求可核對，記錄保留的整個小節，但理由須說明該原句自己的斷言。

## 提交前檢查

```sh
ruby scripts/verify-body-restructuring.rb
ruby scripts/test-body-restructuring.rb
ruby scripts/show-body-map.rb
git diff --check
git diff --check 350668eb14ede247af22c782323beebf940c2a5f..HEAD
```

常駐入口包含五批追溯、改寫清單目的列全文比對及逐字去重，另檢查未整理文件、全部 rules 的登錄差異與位元組、驗收列、ID 集合、原句完整性及本地連結。負向測試只在暫存複本變異，不能在分支上「先破壞再還原」。測試含故意漏句、錯小節、失效錨點、清單竄改、驗收縮水、未登錄共通改動、隱藏檔及行尾差異。

人工作最後核對：每個原句的條件、禁止事項、例外邊界、適用對象是否全部在目的地；不要因有程式碼標記就認定是 Java 增量，也不要因沒有標記就刪掉。檢查不證明語意等價、來源充分或沒有換句話說的重複。
