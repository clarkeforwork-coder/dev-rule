## 判斷、暫停與未做事項

共通每一處改動的決策列、來源與驗收去向見[共通側決策](body-restructuring-common-decisions.md)。唯一因涵蓋不足而暫停的是 VO-10 摘要首句：一般重要行為測試不足以證明全部專屬型別邊界值及「不能只測建立成功」已逐項承接，所以原句仍在。這一項沒有完成刪文，也沒有自行新增義務或驗收。

JN-01 的「依業務要求必須存在卻不存在」及 JN-03 的缺值分支與替代值語意保留在 Java，避免用一般失敗分類取代具體觸發條件。JN-05／11 按核准規則整條保留；JN-07 的標註／文件／行為一致與執行期驗證仍留語言落實說明。BM-04 選 B 前核對 Java 第 4 條與失敗驗收，半成品拒絕保留，必要欄位另由共通既有映射欄位驗收承接。

按階段範圍未做其餘 14 份正文、集合合併、74 個共通錨點改名、M4 驗收搬移與其他文件 L2／L6。這些不是遺漏，已列於[待決清單第九節](pending-decisions.md#九正文整理階段-a-的核准與執行狀態)。

## 後續平行處理的易錯處

- 把「有引用」當作逐個斷言已涵蓋；尤其是條件、例外邊界、失敗後狀態與必須存在等限制。
- 移除驗收入口時連同正文中獨立要求一起丟掉；JN-10 的非法資料輸入句必須搬到有效位置。
- 把整句判成重述而刪掉混合的 Java 限制，或把所有標註／API 名稱都當成實質增量。
- 多人改共用檔案、整批重生 JSON 或先改共通錨點；各工作者只能動分派檔案與自己的紀錄。
- 整份合併只搬正文，漏驗收列、入站連結、批次目的地與改寫清單；合併留協調者獨立整合。
