## 檢查範圍與維護

[逐句差異清單](acceptance-check-policy.json)以 `6a16349` 的行號、刪文及增文重建每份規範的受保護版本。檔案清單也受保護。沒有驗收整節白名單，沒有程式內特定句子的跳過判斷；若更新驗收，必須一併審查清單中的精確差異。新增完整驗收列可被接受，但不能覆寫或刪除既有列；逐字重複、壞連結與重複錨點仍各自拒絕。這份清單是審閱設定，修改它仍須人工審查，不能當成語意正確的自動證明。

[已改寫清單](acceptance-rewritten-fragments.json)只接受原片段 ID、原文、目的地、目的列實際文字與理由全部一致的改寫。未列入者必須在目的列逐字存在。獨立錨點只取緊接的一段，不取整個章節。

重現指令：

```sh
ruby scripts/verify-acceptance.rb

```

`--target` 整體匯出指定提交，全部規則、文件、差異清單、改寫清單與統計均讀該提交；沒有清單的舊提交明確拒絕。`--baseline` 可覆寫指定批次的原文來源；`--rules-baseline` 須與差異清單的基準一致。`--trace-only` 保留為批次重現介面，但不會關閉常駐全檔保護。需要檢查當批範圍時加 `--check-scope`：比對範圍外 Java 全文及所有 Java 正文；不能對後續已合法整理的工作區套用舊批次範圍。歷史提交可使用其自身腳本，但那些舊腳本的盲點不因此消失。

負向測試以暫存複本執行 T1 至 T10（T6 分 a／b），T3 預期通過，明列為人工檢查項目；其他變異必須被拒絕。實際輸出由 [驗證紀錄](acceptance-verification-results.md)產生器直接擷取，不手寫結果。未處理的正文去重、L2／L6／L7 與共通驗收最終歸位見[待決清單](pending-decisions.md)；沒有不同意審閱發現而逕自略過的項目。
