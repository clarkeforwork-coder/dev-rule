# 共通規範與 Java 規範分離總結

## 目的與最後結構

這次整理讓同一項要求有清楚的主要維護位置：跨語言原則放在 `rules/` 的共通主題，Java 語法、標準 API、版本及執行模型的具體要求放在 `rules/stacks/java/common/`。Java 引用共通要求，並補足實際語言路徑；引用不是豁免，共同驗收仍須透過專案實際使用的 Java 型別、API 與框架執行。

原則是先保住要求，再減少重複。只有能指出具體承接來源的句子才移除；涵蓋不夠直接就保留或還原，沒有為了讓表格變短而縮小範圍。正式 Java 文件已改用小標題與語意錨點；原編號只留在追溯紀錄。74 個共通歷史錨點改用語意名稱，舊名仍在同一位置作相容別名。每個有整條移除的分組提供可讀指路，讀者不必知道歷史代號才能找到要求。

驗收依現有主題結構維護。本輪只把介面用途與多步驟／部分成功兩列移回各自規則檔，規範驗證原位置保留連結；其他主題不全面搬移。工作擁有者與結果接收、例外後狀態與全部／部分成功的驗收互相引用並說明分工，原斷言均保留。

## 共通義務的變化與移回 Java 的內容

第一輪經核准把集合所有權、資源有效期、非同步完成條件、數值日期時間與文字等共同契約集中到共通主題，也補足既有型別安全、空值、領域、映射及檢查規則的共同要求。這是已核准的歸屬調整，不代表可把後續每個 Java 注意事項都提升為共通；各條依據仍見[遷移紀錄](java-rule-migration.md)。

後續正文整理另外明確核准兩項跨語言義務：非同步結果須有接收路徑且不得丟棄故障；批次修改不得從「拋出例外」推定「未修改」，並保留不要求所有集合操作有交易能力的邊界。兩者分別列於[結果接收](../rules/coding/concurrency-and-async.md#async-result-reception)與[失敗後狀態](../rules/coding/error-handling.md#failure-state-guarantee)。其他摘要只登錄或引用既有來源，沒有趁收斂文字擴充義務。

反之，共通摘要中的記憶體可見性、不同業務面向分別建模，以及映射不得略過欄位或產生不完整物件掩蓋失敗，依決策移回 Java 維護。最後一項已逐字放回 Java 映射正文，並補驗收；日後新增其他語言時，不能假設它自動具有共通效力。

## 保守保留、未做事項與限制

仍有共同背景與 Java 說明語意相近，例如非同步執行資源及鎖、Entity 識別碼的集合契約、值物件正規化、集合失敗狀態與動態呼叫故障。獨立審閱指出涵蓋不夠直接的句子已還原，沒有宣稱全面消除語意重複。五條曾被判為「驗收入口」的條文仍整條留在 Java：值物件測試、狀態模型驗收、反射／抑制的兩條檢查要求及數值時間文字驗收。歷史識別碼 VO-10、ST-10、RF-07、RF-08、NT-14 只用來追溯這五條。

集合文件仍有多條 Java 專屬內容，不符合「只剩失敗狀態提醒才合併」的條件，所以不併檔。規範驗證其他主題的全面搬移、領域與映射摘要和驗收的語意重疊，只盤點不改。例外治理尾句、介面與部分成功政策、保守保留的 Java 驗收均維持；Java 小節錨點不再改名。這些取捨避免為版面一致而降低既有要求。

19 條早期改成引用的 Java 條文，其整理前原文從未提交，儲存庫無法還原，因此不能證明最早原文被完整涵蓋。逐句追溯以可取得的提交為證據，不能補造遺失內容。工具能檢查字面保存、錨點、連結及核准差異，無法證明某個共通來源在語意上充分承接原句；這部分仍需人工審閱。

## 日後維護

使用 Ruby 2.6 或相容版本，從儲存庫根目錄執行：

```sh
ruby scripts/verify-body-restructuring.rb
ruby scripts/verify-final-acceptance.rb
ruby scripts/record-body-verification.rb
git diff --check
```

第一個命令核對逐句去向、現行精確轉換與連結；第二個核對本輪驗收錨點唯一、搬移及明列增補；第三個執行全部測試與檢查並重生實際輸出。`verify-body-sentences.rb` 另可重跑句子多重集合比對，先逆轉明列的最後階段修正。舊驗收階段測試以封存基準執行，現行驗收另有追溯與精確差異檢查，不能拿封存通過代替現行通過。

目前工具刻意釘住整理基準；日後正式新增或修改規則，應先核准要求及更新逐筆紀錄和相應測試，不得直接放寬白名單或移動基準來消除失敗。歷史追溯、別名清冊與獨立審閱的證據限制都應保留。
