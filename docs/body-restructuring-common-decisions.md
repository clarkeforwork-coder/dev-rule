## 第五次審閱修正與撤回責任

BM-04 的禁止句先恢復在共通摘要，選 B 不變，刪除時點延後；Java 目前只有引用與半成品驗收，沒有「不得略過欄位」的正文，先前聲稱完整承接的判斷已更正。後續工作者必須用 imports 逐字移入，協調者在全部合併後才刪共通句。部分成功繼續引用既有主要來源，其他已核准收斂不退回。VO-10 摘要首句維持原文，不刪、不改。

L8：CA-06 的接收驗收與 ca-01 擁有者驗收部分重疊；前者檢查結果分類與接收路徑，後者檢查誰負責與移交。CO-08 的例外後狀態驗收與規範驗證的部分操作驗收部分重疊；前者檢查不能從例外推定未修改，後者檢查全部／部分成功及項目對應。依本輪指示，不改這兩個提交新增的條文與驗收列，分工與去重留待全部合併後處理。

L9：撤回 `b1d2f33` 或 `5a16124` 時，除了規則及該提交所帶的 `common/ca-06.json`／`common/co-08.json`，協調者必須同步處理下列後續位置，不能把「乾淨 revert」當成文件敘述仍正確：

- 本文件的「新增義務的獨立提交」表、分工說明及撤回狀態。
- `docs/pending-decisions.md` 第九節 CA-06／CO-08 執行列及本輪狀態。
- `docs/body-restructuring-stage-a.md` 提交表與已列管敘述；`docs/body-restructuring-review-5.md` 的本輪結果。
- `docs/body-restructuring-guide.md` 的提升後混合處理例外及共同驗收新增連結；`scripts/body-structure-checks.rb` 中對應的驗收增文白名單。
- 後續若已整理併發／集合，重新核對其 Java 正文、JSON 移除子句來源與共同驗收連結，不得留下指向已撤回錨點的來源；必要要求須回到仍有效的 Java 位置。
- 重新執行檢查，使用 `scripts/record-body-verification.rb` 更新驗證紀錄。

兩份共通紀錄的名稱列於工具允許清單，但允許因撤回而缺少；不允許自行新增其他共通紀錄檔。這不是重新核准或取消提升義務的權限。

## 第六次修正補註

前述映射摘要收斂的歷史說明不代表現況仍使用「邊界不可變性」與 co-01 作為摘要連結；第五次修正已恢復整份邊界物件與程式碼設計等引用，請以現行規則及逐塊紀錄為準，本輪不改共通檔。當併發或集合 Java 文件已整理，對應提升提交的單獨撤回檢查不再適用：驗證產生器仍執行撤回測試，但輸出 applicable=false 與相依來源須同步調整的理由，不將它宣稱為獨立撤回成功。現行兩份均 pending，仍實際測試兩次獨立撤回。
